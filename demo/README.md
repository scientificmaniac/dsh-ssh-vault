# dsh-ssh-vault-demo

给 `dsh-ssh-vault` 拍**市场店面截图**用的伴生插件。

它用**虚构数据**渲染出与真插件一致的三个界面，因此截图里不会出现任何真实内网地址、账号或口令。它不发起任何网络连接，不读保险库，也不注册任何真实工具。

**不要把它提交到插件市场。** 它是截图工具，`private: true`，也不在真插件的 `files` 清单里。

## 装了什么

| 界面 | 位置 | 假数据 |
| --- | --- | --- |
| 设置页「SSH 连接（演示）」 | 设置 → 侧栏 | 5 台虚构主机（3 绿 1 红） |
| 工具终端卡片 | 对话 | `demo_ssh_run` / `demo_ssh_probe` / `demo_ssh_transfer` |
| `/demo` 双卡片 | 对话 | 连接状态 + 命令执行 |

工具名与 section id 都与真插件**错开**，两者可以同时安装：

| | 真插件 | 本插件 |
| --- | --- | --- |
| 工具 | `ssh_run` / `ssh_probe` / `ssh_transfer` | `demo_ssh_*` |
| section | `ssh-vault` | `ssh-vault-demo` |
| 命令 | `/hosts` | `/demo` |

## 安装

```bash
# 在本仓库根目录执行
dsh plugin --profile desktop install ./demo
```

**重启 DSH**（Host 侧的工具与命令在启动时加载）。

要装到虚拟机里那台 DSH，把整个仓库（或仅 `demo/` 目录及其两个 js 文件）复制过去，再执行同样的命令。

## 截图

### 1. 设置页

设置 → **SSH 连接（演示）**。

页面顶部是标题、说明、版本行与三个按钮；下面依次是 5 张主机卡片，每张带状态点（绿=连通、红=不通）、别名、连通徽章、标签，以及地址/账号/认证/备注四个字段和编辑/测试连接/删除三个按钮。

点「添加连接」会让一张空表单展开在列表上方——用来截「新建连接」那张。

### 2. 工具终端卡片

在对话里说：

```
用 demo_ssh_run 在 analytics 上跑 df -h
```

或直接让模型调用。卡片标题是「主机 · 命令」，下面是等宽输出区，标题栏左侧一个绿点表示完成。

`demo_ssh_probe` 与 `demo_ssh_transfer` 同理，分别渲染探测输出与传输进度。

### 3. `/demo` 双卡片

在输入框里输入 `/demo` 回车。

输出会拆成两张卡片：「连接状态」列出两台可达主机的摘要，「命令执行」给出一次 `df -h` 的输出。第一张卡标题栏左侧绿点、中间居中显示「连接状态」。

## 卸载

```bash
dsh plugin --profile desktop remove dsh-ssh-vault-demo
```

**重启 DSH**。真插件不受影响。

## 换成自己的演示内容

假数据集中在两个地方，改完重装即可：

- `index.js` 的 `HOSTS` 数组 —— 主机列表、探测输出、命令输出
- `client.js` 的 `DEMO_HOSTS` 数组 —— 设置页卡片（与上面保持一致）

地址请继续使用 RFC 5737 文档段（`192.0.2.0/24`、`198.51.100.0/24`、`203.0.113.0/24`），它们专为此类用途保留，不会与真实网络冲突。

## 截图建议

- **深色主题**下卡片对比度最好，与终端输出也协调
- 设置页**宽度收窄**到 600–700px 左右，主机卡片不会拉得过长
- `/demo` 双卡片建议**上下一起截**，能同时展示两个状态点
- 截完存成 `assets/screenshot-*.png`，再在仓库根写 `screenshots.json` 列出它们
